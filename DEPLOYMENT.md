# Deployment preparation

Status: configuration prepared; nothing has been deployed yet.

## Vercel frontend

The root vercel.json serves only frontent/ as a static site. No build or dependency install is needed. .vercelignore excludes backend source and local secrets from uploads.

Once the Render service is live, set its HTTPS URL as the frontend's default API connection before publishing the final frontend deployment. A localhost API URL cannot serve public users.

## Render backend

render.yaml defines a Python web service with a free instance, /Health check, frozen uv dependency installation, and Uvicorn bound to Render's PORT.

Required secure service environment variables:
- DATABASE_URL: a reachable PostgreSQL connection URI compatible with SQLAlchemy and the checkpoint saver.
- OPENAI_API_KEY: credentials for the selected hosted model service.
- SECRET_KEY: generated by Render.
- ALGORITHM: HS256.

Remaining requirements before deployment:
1. Install/connect Vercel and Render integrations.
2. Provide or create a Git hosting repository for Render's source checkout. No Git remote was configured when these files were prepared.
3. Choose a hosted model service and configure the backend to use it. The current model endpoint is http://localhost:20128/v1, which is not reachable from Render.
4. Configure hosted PostgreSQL and the model credential securely in Render; do not commit them.
5. Review authentication storage before accepting real users: the current implementation stores passwords directly.
6. Deploy the backend, verify health/auth/chat/approval/history, wire the frontend API URL, then deploy and verify the frontend.

The local .env file has been excluded from Git's index without deleting it. If credentials were published elsewhere previously, they require rotation; ignoring a file does not remove prior history.
